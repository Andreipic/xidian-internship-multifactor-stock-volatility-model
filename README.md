# BYD Stock Price Volatility Analysis and Prediction

Internship project — Xidian University, School of Electronic Engineering.
Supervisor: Professor Ru Zong. Student: Petru Andrei Piculescu (Polytech Nice Sophia / MAM4).

Builds and validates a volatility analysis and prediction pipeline for BYD Co., Ltd. (002594.SZ):
signal denoising (Kalman / wavelet), external-factor correlation, an ARIMA baseline and a recursive
multivariate LSTM, SHAP interpretability, conformal prediction intervals, and a Phase 4 robustness
framework (volatility regimes, stress scenarios, a ±5% risk-warning indicator).

## Reproducing the results

**Clone and run in order — Phase 3 must run before Phase 4, since Phase 4 loads Phase 3's model rather
than retraining it.**

```
git clone <repo-url>
cd BYD-volatility-analysis
```

Open each notebook (Jupyter locally, or upload to Colab) and run top to bottom:

1. `notebooks/phase1_data_collection.ipynb` — collects BYD OHLCV and initial factors, saves `data/byd_phase1_dataset.csv`
2. `notebooks/phase2_external_factors.ipynb` — adds the full external factor set, saves `data/byd_all_factors_dataset.csv`
3. `notebooks/phase3_signal_and_models.ipynb` — signal filtering, ARIMA, LSTM training, SHAP, prediction intervals. **The trained model is already committed** (`models/lstm_recursive_corrected.keras` + scalers), so this notebook loads it instead of retraining, and reproduces the numbers below exactly.
4. `notebooks/phase4_robustness.ipynb` — loads the Phase 3 model (fails loudly if it's missing, rather than silently retraining a different one) and runs the regime/stress-scenario robustness assessment.

Each notebook auto-detects whether it's running in Colab or locally/cloned; no path editing needed.

### On reproducibility
The LSTM is committed pre-trained specifically because TensorFlow's GPU (cuDNN) training isn't
bit-for-bit reproducible across runs, even with a fixed seed. If `models/lstm_recursive_corrected.keras`
is deleted and Phase 3 is re-run, expect the general conclusions to hold (LSTM under the project's 8% MAPE
threshold, beating the naive baseline) but not necessarily the exact figures below.

## Headline results (2023–2025 test set)

| Model | MAPE |
|---|---|
| ARIMA(1,1,1) | 4.94% |
| Naive (walk-forward) | 6.68% |
| LSTM, recursive, raw | 5.33% |
| **LSTM, bias-corrected** | **4.70%** |

Conformal prediction interval coverage (704 test points): 90.3% at nominal 80%, 95.9% at nominal 95%.

Phase 4 robustness (bias-corrected LSTM + conformal intervals):

| Regime | MAPE | Alert rate |
|---|---|---|
| Calm | 3.47% | 4.5% |
| Normal | 5.27% | 6.5% |
| Volatile | 6.75% | 11.1% |

Stress scenarios: policy shock 6.07% mean MAPE, market crash 7.25% mean MAPE (averaged over 5 anchor points).

## A note on the debugging history

The first working version of the LSTM reported MAPE = 1.77%, which turned out to be wrong: a data-leakage
bug in the recursive forecast reconstruction let the model see information it shouldn't have had. Finding
and fixing this (documented in `notebooks/phase3_signal_and_models.ipynb`, section "Historique des
corrections") is treated as part of the deliverable rather than something to hide -- the corrected,
honestly-validated MAPE is 4.70%.

## Known limitations

- Lithium carbonate price and Caixin PMI were attempted as external factors (Phase 2) but dropped: no
  free data source returned usable history for either.
- Exogenous features are approximated by their last known value during the 22-day recursive forecast
  (a standard simplification); a future improvement would model them dynamically (e.g. VAR).
- Phase 4 stress scenarios use synthetic shocks (as required by the internship subject) rather than
  replaying historical episodes directly, to avoid testing on data close to the model's own training window.
